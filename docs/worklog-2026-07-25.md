- 콘텐츠 제작은 **5개 이상 동시**, 작성 1건마다 **검증 1건 페어링**.
- 작성·검증 에이전트 모두 **Opus**.
- 절차도 구조 요건: gateway는 출구 2개 이상 + 간선 라벨, 각 호 1:1 전개 금지, 막다른 길 금지, `loop`는 되돌아가는 간선에만, `current`는 파일당 1개, 내부 행정은 노드로 만들지 않음, 노드 배열은 stage 순서와 일치.
- 파이프라인 실행 순서: `sync:sources --write` → `verify:articles --write` → `populate-article-texts` → `generate:catalog` → `generate:verification-queue` → `validate:data`. institution JSON은 **1칸 들여쓰기**로 쓴다.
- CLI 서브커맨드는 언더스코어(`search_law`, `get_law_text`, `search_admin_rule`, `get_admin_rule`). 행정규칙 전문은 **행정규칙ID가 아니라 일련번호**로 조회해야 나온다.
